> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add three new troubleshooting levels that teach cable failure recovery (L11), OSPF redundancy + multi-failure (L12), and VLAN inter-VLAN routing recovery (L13).

### Task 2: Create `levels/level_12.json` — Dual Failure / OSPF Redundancy

**Files:**
- Create: `levels/level_12.json`

Level 12 introduces OSPF and redundancy. The primary path (RTR-1 → RTR-2 → RTR-3) is blocked because RTR-2 has crashed. The backup direct link (RTR-1 → RTR-3) is also broken. Player must fix **either** failure — restoring the crashed router OR the broken backup link — and OSPF reconverges automatically. This shows that redundant networks can have multiple recovery paths.

**Topology:**
```
PC-A ── RTR-1 ──── RTR-2(crashed) ──── RTR-3 ── PC-B
         │   \                            /
         │    └────[broken direct]───────┘
         └──────────────────────────────────────┘
```

Positions (x, y):
- PC-A: (-540, 0)
- RTR-1: (-270, 0)
- RTR-2: (0, 120)  ← below the primary path
- RTR-3: (270, 0)
- PC-B: (540, 0)

IP addressing:
- PC-A: 10.12.0.2/24, gateway 10.12.0.1
- RTR-1 port0: 10.12.0.1/24 (to PC-A)
- RTR-1 port1: 10.13.0.1/24 (to RTR-2, primary)
- RTR-1 port2: 10.14.0.1/24 (to RTR-3, backup — broken cable)
- RTR-2 port0: 10.13.0.2/24 (to RTR-1)
- RTR-2 port1: 10.15.0.1/24 (to RTR-3)
- RTR-3 port0: 10.14.0.2/24 (to RTR-1, backup — broken cable)
- RTR-3 port1: 10.15.0.2/24 (to RTR-2)
- RTR-3 port2: 10.16.0.1/24 (to PC-B)
- PC-B: 10.16.0.2/24, gateway 10.16.0.1

All routers: `ospfEnabled: true`, `routerId` set.

### Task 3: Create `levels/level_13.json` — VLAN Outage

**Files:**
- Create: `levels/level_13.json`

Level 13 puts VLAN inter-routing in a failure scenario. SW-1 is healthy and pre-configured with trunk/access ports. RTR-1 is pre-configured with sub-interfaces for VLAN 10 and VLAN 20 — but it has crashed. PC-Sales (VLAN 10) and PC-Eng (VLAN 20) cannot reach each other because the inter-VLAN gateway is down. Player restores RTR-1 and both VLANs can route again. The briefing hints that the scene can be saved with Ctrl+S after fixing.

**Topology:**
```
PC-Sales(VLAN10) ── SW-1(trunk p0) ── RTR-1(crashed)
PC-Eng  (VLAN20) ──/
```

Positions:
- PC-Sales: (-350, -100)
- PC-Eng:   (-350,  100)
- SW-1:     (-100,    0)
- RTR-1:    ( 150,    0)

IP addressing:
- PC-Sales: 10.10.0.2/24, gateway 10.10.0.1
- PC-Eng:   10.20.0.2/24, gateway 10.20.0.1
- RTR-1 sub-interface VLAN 10: 10.10.0.1/24
- RTR-1 sub-interface VLAN 20: 10.20.0.1/24
- SW-1 has no IPs (Layer 2 switch)

SW-1 port configuration:
- port0: trunk (to RTR-1) — carries both VLAN 10 and 20
- port1: access vlan 10 (to PC-Sales)
- port2: access vlan 20 (to PC-Eng)

RTR-1 sub-interfaces (both on port 0, the trunk link):
- `{ "port": 0, "vlan": 10, "ip": "10.10.0.1/24" }`
- `{ "port": 0, "vlan": 20, "ip": "10.20.0.1/24" }`
